## 1. 지원 상황

- **넥토리얼 = 넥슨 공채 프로그램 이름** (특정 스튜디오/게임 아님). 합격 시 넥슨 산하 어느 스튜디오·게임에든 배치 가능, **배치처 미정**.

  - 참고: 빈딕투스(디파잉 페이트)는 출시가 2027년 이후로 조정됨.

### AI 면접 상세 (넥토리얼 공식 안내 이미지 `nextorial_aitest_introduce.png` 기준)

- **일시: 2026-09-12(토) 오후 중 일괄 진행. 해당 일자에만 응시 가능. 재응시 불가.**

## 2. 작업 방식 (사용자 선호 — 반드시 지킬 것)

- 답변은 **60초 제한, 실제로는 ~50초 분량**으로 짧고 간결하게. 천천히 말해서 시간 채우는 전략.
- **암기하기 쉽게** — 문장 짧게, 군더더기 없이.
- 오프닝은 **"저는 ~한 경험이 있습니다" 식 스토리 훅** 선호 (필살기 먼저). ※ 단 상황질문은 예외(아래).
- **면접왕 이형(유튜버) 프레임 참고**: 답변 = 자기 자랑 나열이 아니라 "회사가 필요로 하는 것 + 내가 채울 근거". 약점 질문은 진짜 약점 + 구체적 사례 + 극복 노력. 지원동기 = 직무 동기(경험 근거) + 회사 동기(그 회사만의 특징) + 구체적 기여. 회사명만 바꿔도 되는 답변은 탈락.
- 각 문항 답안 작성 후 **아래 세트를 파일에 직접 반영**:
  - `[예시 답안 - 약 N초]`
  - `[주요 키워드]` (표 형태 아님, 불릿)
  - `[암기용 N비트]`
  - `[예상 후속 질문 대비]`
- 대안 버전이 나오면 `[대안 - ...]` 로 함께 보존.
- 진행 방식: 한 문항씩(또는 한 파일씩), 사용자 확인받고 다음으로. 초안 → 사용자 피드백 여러 번 → 확정 후 반영.
- **팩트 원칙(매우 중요)**: 사용자는 지어낸 일화·"들은 적 없는 칭찬"·과장된 성과를 강하게 거부함. 답안에 쓸 사례는 `지원 이력/`·노션 정리에서 검증되는 것만. 애매하면 사용자에게 "이거 실제로 하시나요?"로 먼저 확인. 자기 인식/의도 수준은 "~하려 한다"로 쓰되 사용자 승인 필요.
- 여러 문항에 걸친 답변 간 **논리 일관성** 체크 필수 (예: 심화 5 "사람 중심" ↔ 심화 8 우선순위 / 기본 7·심화 7·전공 10 비전 정합).
- **상황질문 전용 방침**: 내 경험담 X, 원칙·판단기준 위주, 답안 30~35초로 짧게. 양자택일 문항은 하나를 명확히 고르고 "이유 + 예외" 구조. 상황대응 문항은 "1단계 구분 → 대응 → 필수 공유·기록" 구조.

## 3. 진행 현황

| 파일 | 상태 |
|---|---|
| `기본질문.txt` | **1~10번 초안 완료.** 1번은 사용자가 직접 편집한 버전이 파일 상단에 있음 — **건드리지 말 것**. 나머지는 초안 상태(사용자 세부 검토 전). |
| `상황질문.txt` | **1~10번 완료.** 사용자가 방식 확인함("이렇게 정리하자"). 큰 이의 없음. |
| `심화질문.txt` | **1~10번 완료.** 4·5·8·9·10번은 사용자 피드백 여러 차례 반영해 **재작성·확정**. 1·2·3·6·7번은 1차 초안 상태(사용자가 이의 안 함). |
| `전공질문.txt` | **1~10번 1차 초안 완료.** 배경지식 기반. 사용자 검토 대기. **[확인 필요] 2건**(아래 9번 항목) 미해결. |

### 전공질문.txt 미해결 확인 사항 (다음 세션 최우선)

1. **3번 (Git/브랜치/코드리뷰)**: 마상소프트 실제 형상관리 방식 미확인 → 일반론으로 채워둠. 사용자에게 물을 것: 기능 브랜치 쓰는지 / 릴리스 브랜치까지 가는지 / 코드리뷰가 PR 기반인지 구두인지, 필수인지 / 충돌·머지 실제 사례.
2. **9번 (본인 강점)**: **사용자 전공자 여부 미확정.** 현재 "전공자"로 가정하고 작성(학생 때 유니티로 게임 개발 이력 근거). 비전공자면 프레임을 "게임을 직접 만들며 시작 → 필요에서 기초를 채움 → 실무 감각이 강점"으로 교체. (9번 [후속]에 교체 프레임 메모 있음.)

### 그 외 트리밍 대상
- 전공 4·6·8번 답변이 ~50초로 약간 김. 확정 시 트리밍.

## 5. 확정된 핵심 메시지 (일관성 유지)

- 한 줄 정체성: **"라이브를 안정적으로 지키면서, 다음 개발이 쉬워지도록 구조를 개선하는 서버 프로그래머"**
- 강점 축: **안정성 + 확장성**
- 공채 대응 논리: **"배치 미정 = 오히려 나의 강점(5개 라이브 서비스 병행으로 낯선 프로젝트 빠른 적응)과 맞음"**
- 넥슨 회사 동기: **"20년+ 초장수 라이브 서비스 다수 = 국내 거의 유일 / 레거시를 안고 확장을 최대 규모·최장 기간 해온 곳"** + "MMORPG를 가장 오래·많이 만든 회사"
- 최종 목표: 윈도우·리눅스 크로스플랫폼 게임 서버 엔진 → 여러 개발사가 MMORPG를 쉽게 만들게 → MMORPG 전성기 부활. "그런 엔진은 책상에서 안 나온다 → 넥슨에서 대규모 MMO 경험 필요"로 회사와 연결.
- 약점: 정규화 등 기술적 완결성에 몰입하다 데이터 쓰는 사람(기획자) 편의를 뒤늦게 챙김 → 구조 확정 전 기획자 입력 흐름부터 확인.
- **직업 선택 1순위(심화 5번, 사용자 인터뷰로 도출·확정): "함께 일하는 사람".** 근거: 유지/이탈도 인간관계, 하나만 고르면 사람. 정체성(유저들이 관계 맺고 오래 머무는 세계를 만들고 싶다)과 같은 뿌리. 2순위 = 이유를 이해하고 구조를 직접 설계할 수 있는 환경(배경 없이 "일단 만들어" 지시에 의욕 꺾임).
- **심화 8번(개인 전문성 vs 팀 협업) = "팀 협업 우선"으로 확정.** 근거: 적은 인원 다수 서비스 → 혼자만 아는 구조 = 팀 약점. (첫 초안 "개인 전문성 우선"에서 사용자 요청으로 뒤집음 — 심화 5 "사람 중심"과 일관성.)
- 개발자가 된 이유(전공 1번): "사람들이 게임 안에서 관계를 맺고 오래 머무는 그 바탕을 서버에서 만들고 싶다" (자소서 원문 기반, 심화 5와 같은 뿌리).

## 6. AI 면접 성격 & 전공 지식 대비 방향 (2026-09-09 세션에서 사용자와 정리)

**결론: 깊은 CS 이론 문제는 거의 안 나올 것.** 근거 — 코딩테스트 없음 + "여러분의 이야기로 시작" + AI가 진행하는 50분 대화(사람처럼 깊게 파고들기 어려움, 깊이보다 폭). 교과서형(B+트리, 뮤텍스 vs 세마포어 등)은 이후 실무·기술 면접 자리.

**단, "기본기" 확인 수준은 나올 수 있음.** 대개 본인 답변에 걸어서("왜 그 방식?", "트레이드오프는?"). → 아래 개념을 **본인 경험에 붙여 ~50초로 설명**할 수 있게 준비. (상당수는 전공질문 파일 [예상 후속 질문 대비]에 이미 포함)

| 개념 | 걸 수 있는 내 경험 |
|---|---|
| server authoritative(서버 최종 판정) 왜 중요한가 | 재화·아이템 어뷰징 차단 |
| 프로세스 vs 스레드 / 왜 스레드 분리 | TuxBase I/O 스레드 ↔ 콘텐츠 스레드 + LockQueue |
| TCP가 스트림이라 생기는 문제 | RingBuffer, 패킷 경계 처리 |
| DB 인덱스 / 트랜잭션 / 락 기초 | MySQL 프로시저·파티셔닝 작업 |
| 파티셔닝이 뭔지, 왜 쓰는지 | 로그 누락 건 |
| Redis를 왜 쓰는지 (캐시/공유 상태) | 킹스레이드 |
| 비트플래그의 장단점 | 출석 상태 저장 (64일 제한 → 문자열 개선안) |
| 정규화 vs 반정규화 트레이드오프 | 출석판·무기 튜닝 (+ 약점 답변) |
| 분산 서버 아키텍처 개념 | 월드·채널·존 분리 / 서버 간 MQ·RPC / 공유 상태 Redis (개인 프로젝트는 스레드 분리 수준까지) |

**과투자 금지**: 컴파일러 이론, 그래프 알고리즘, OS 스케줄링 세부.
