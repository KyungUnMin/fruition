# AI 면접 준비 — 핸드오프 문서

> 다른 PC의 새 Claude 세션에서 이어서 작업할 때 이 문서부터 읽으면 됩니다.
> (이 세션은 2026-09-08에 진행. 세션 자체는 이전 불가 — 이 문서 + 답안 파일 + `지원 이력/` 폴더로 이어받음)

---

## 1. 지원 상황

- **넥토리얼 = 넥슨 공채 프로그램 이름** (특정 스튜디오/게임 아님). 합격 시 넥슨 산하 어느 스튜디오·게임에든 배치 가능, **배치처 미정**.
- 지원 직군: **게임 서버 프로그래머**
- **AI 면접** 예정 (질문당 답변 시간 60초)
- 본인은 마비노기 영웅전 / 마비노기 IP 팬. 가능하면 빈딕투스·마비노기 이터니티 희망하나 지원 동기는 그걸로 잡지 않음.
  - 참고: 빈딕투스(디파잉 페이트)는 출시가 2027년 이후로 조정됨.

## 2. 작업 방식 (사용자 선호 — 반드시 지킬 것)

- 답변은 **60초 제한, 실제로는 ~50초 분량**으로 짧고 간결하게. 천천히 말해서 시간 채우는 전략.
- **암기하기 쉽게** — 문장 짧게, 군더더기 없이.
- 오프닝은 **"저는 ~한 경험이 있습니다" 식 스토리 훅** 선호 (필살기 먼저).
- **면접왕 이형(유튜버) 프레임 참고**: 답변 = 자기 자랑 나열이 아니라 "회사가 필요로 하는 것 + 내가 채울 근거". 약점 질문은 진짜 약점 + 구체적 사례 + 극복 노력. 지원동기 = 직무 동기(경험 근거) + 회사 동기(그 회사만의 특징) + 구체적 기여. 회사명만 바꿔도 되는 답변은 탈락.
- 각 문항 답안 작성 후 **아래 세트를 파일에 직접 반영**:
  - `[예시 답안 - 약 N초]`
  - `[주요 키워드]` (표 형태 아님, 불릿)
  - `[암기용 N비트]`
  - `[예상 후속 질문 대비]`
- 대안 버전이 나오면 `[대안 - ...]` 로 함께 보존.
- 진행 방식: 한 문항씩, 사용자 확인받고 다음으로. 초안 → 사용자 피드백 여러 번 → 확정 후 반영.
- **팩트 원칙(중요)**: 사용자는 지어낸 일화·"들은 적 없는 칭찬"·과장된 성과를 강하게 거부함. 답안에 쓸 사례는 `지원 이력/`·노션 정리에서 검증되는 것만. 애매하면 사용자에게 "이거 실제로 하시나요?"로 먼저 확인. 자기 인식/의도 수준은 "~하려 한다"로 쓰되 사용자 승인 필요.
- 여러 문항에 걸친 답변 간 **논리 일관성** 체크 필수 (예: 심화 5 "사람 중심" ↔ 심화 8 우선순위).

## 3. 진행 현황

| 파일 | 상태 |
|---|---|
| `기본질문.txt` | **1~10번 초안 완료** (1번은 사용자가 직접 편집한 버전이 파일 상단에 있음 — 건드리지 말 것) |
| `상황질문.txt` | **1~10번 초안 완료** (사용자 검토 대기). 방침: 내 경험담 X, 원칙·판단기준 위주, 답안 30~35초로 짧게 |
| `심화질문.txt` | **1~10번 완료. 4·5·8·9·10번은 사용자 피드백 반영해 재작성·확정.** 1·2·3·6·7번은 초안 상태(미이의). 경험담이 필요한 문항만 사례 사용, 나머지는 짧게 |
| `전공질문.txt` | 미착수 (다음 작업 대상) |

## 4. 소재 사용 현황 (중복 회피용)

핵심 에피소드가 몇 개 안 되므로, 같은 소재를 여러 문항에서 헤드라인으로 반복하지 말 것.

| 소재 | 사용된 문항 |
|---|---|
| 로그 누락 개선 (일 12만 건, 파티셔닝 프로시저 Bulk Insert 실패) | 기본 1번(사용자 편집본 중심), 8번(스트레스—원인 구간 좁히기 사례). **심화 4번(배려·도움 경험) 헤드라인 확정 — "사업팀의 반복 요청을 없앤" 인간적 각도(B안). 오프닝을 "12만 건"으로 시작 금지, 사업팀 상황부터 열 것.** |
| 출석판 범용 구조 재설계 | 기본 2번(확장성 각도), 3번(장점+단점 양면). 심화 4번 후보였으나 탈락 |
| 무기 튜닝 테이블 분리 | 기본 3번 후속. 심화 4번 후보였으나 "위에서 시킨 일=자발성 약함"으로 탈락(사용자 지적) |
| 킹스레이드 Node.js 단기 적응 | 기본 6번, 9번. **심화 1번(가장 힘들었던 경험) 본문 헤드라인** — "첫 2주 정체 → 한 흐름부터" 극복 서사. (심화 1은 미확정 초안 — 사용자 검토 시 교체 가능) |
| 킹스레이드 챌린지 레이드 근거 기반 반대(pushback) | 본문 미사용. 기본 3·6·8번 후속 + **심화 9·10번 후속**에 근거로 등장. 상황질문 최종본엔 미사용 |
| 인수인계 부실 (팀 이슈, 특정 에피소드 아님) | **심화 9번(같이 일하기 싫은 사람) 헤드라인 확정.** "받을 때 대표기능 한 흐름 추적 / 넘길 때 막히는 지점 문서화" — 사용자가 "완전 팩트는 아니지만 이 버전이 낫다"고 승인 |
| 자기 인식 3종 (걱정 많음 / 남에게 폐 끼치기 싫음→혼자 떠안음 / 말 조심) | **심화 10번(주변 평가) 헤드라인 확정.** "직접 들은 평가 없음 → 일하는 모습으로 짐작" 프레임 |
| AI를 역할별 서브에이전트로 분리 | 기본 6번 |
| Boost.Asio 서버 엔진(TuxBase-MMO) 자작 | 기본 7번(비전), 6·7·8번 후속 |
| MMORPG 크로스플랫폼 서버 엔진 비전 → "MMORPG 전성기 부활" | 기본 7번, 10번 |
| 스키드러쉬(스키드마크·패시브 아이템) | 미사용 |

## 5. 확정된 핵심 메시지 (일관성 유지)

- 한 줄 정체성: **"라이브를 안정적으로 지키면서, 다음 개발이 쉬워지도록 구조를 개선하는 서버 프로그래머"**
- 강점 축: **안정성 + 확장성**
- 공채 대응 논리: **"배치 미정 = 오히려 나의 강점(5개 라이브 서비스 병행으로 낯선 프로젝트 빠른 적응)과 맞음"**
- 넥슨 회사 동기: **"20년+ 초장수 라이브 서비스 다수 = 국내 거의 유일 / 레거시를 안고 확장을 최대 규모·최장 기간 해온 곳"** + "MMORPG를 가장 오래·많이 만든 회사"
- 최종 목표: 윈도우·리눅스 크로스플랫폼 게임 서버 엔진 → 여러 개발사가 MMORPG를 쉽게 만들게 → MMORPG 전성기 부활. "그런 엔진은 책상에서 안 나온다 → 넥슨에서 대규모 MMO 경험 필요"로 회사와 연결.
- 약점: 정규화 등 기술적 완결성에 몰입하다 데이터 쓰는 사람(기획자) 편의를 뒤늦게 챙김 → 구조 확정 전 기획자 입력 흐름부터 확인.
- **직업 선택 1순위(심화 5번, 사용자 인터뷰로 도출·확정): "함께 일하는 사람".** 근거: 유지/이탈도 인간관계, 하나만 고르면 사람. 정체성(유저들이 관계 맺고 오래 머무는 세계를 만들고 싶다)과 같은 뿌리. 2순위 = 이유를 이해하고 구조를 직접 설계할 수 있는 환경(배경 없이 "일단 만들어" 지시에 의욕 꺾임).
- **심화 8번(개인 전문성 vs 팀 협업) = "팀 협업 우선"으로 확정.** 근거: 적은 인원 다수 서비스 → 혼자만 아는 구조 = 팀 약점. (첫 초안의 "개인 전문성 우선"에서 사용자 요청으로 뒤집음 — 심화 5의 "사람 중심"과 일관성 맞춤)
